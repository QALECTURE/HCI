# QHO542 Human Computer Interaction
## Week 4 Seminar README: Gestalt Principles, Formative Data Collection, Figma, and Assessment Clinic

**Session type:** Seminar only  
**Duration:** 2 hours  
**Main focus:** Practical application of Gestalt principles, cognition, perception, accessibility, demographics, formative evaluation, and wireframe prototyping.

---

## 1. Purpose of Week 4

This week moves students from general HCI principles into a more structured design and evaluation mindset.

The key message for students is:

> Good interface design is not just about making a page attractive. It is about understanding how users visually group information, how they perceive structure, how they complete tasks, and how feedback data tells us what needs to improve.

Students should understand that every design choice can affect:

- how quickly users understand the page
- how easily users find information
- how much mental effort users need
- how accessible the interface is
- how different demographic groups experience the same design
- how effectively the design supports business and user goals

---

## 2. Week 4 Core Topics

By the end of the seminar, students should be able to explain and apply:

1. Gestalt principles in interface design
2. The impact of Gestalt principles on cognition and perception
3. The effect of user demographics on design interpretation
4. The impact of Gestalt principles on accessibility
5. Formative data collection and analysis using questionnaires
6. Basic wireframing and prototyping using Figma or another suitable tool
7. Assessment preparation for the HCI critical review and prototype work

---

## 3. How This Connects to the Assessment

The assessment requires students to critically review a real website, identify user and business needs, propose interface improvements, build a prototype, and carry out UX testing.

The Week 4 seminar supports this by helping students practise:

- identifying user needs
- identifying business needs
- applying Gestalt principles to improve layout and usability
- thinking about accessibility and demographics
- planning questionnaire-based formative evaluation
- using Figma to create wireframes or prototype screens

In simple terms:

```text
Assessment task = Review website + identify issues + redesign + test users + explain decisions
Week 4 seminar = Learn how visual grouping, perception, and formative data help that process
```

## 4. Previous Context: Formative Data Collection and Analysis

Designing useful and attractive products requires both creativity and evidence.

A design normally evolves through several stages:

```text
Initial idea → concept design → wireframe → prototype → user evaluation → redesign → improved prototype
```

This is called an iterative process.

A design should not be treated as finished just because the designer likes it. It needs to be checked with users.

Formative evaluation helps designers understand what is working and what needs to change while the product is still being developed.

---

## 5. Why We Collect Formative Data

Tell students:

> We do not test only at the end. We test during the design process so we can improve before the final product is submitted or launched.

Formative data helps answer questions such as:

- Are users happy with the interface?
- Can users understand the layout?
- Can users complete tasks quickly?
- Are colours helping or confusing?
- Is the logo simple and memorable?
- Does the grouping of content make sense?
- Is the structure of the form logical?
- Does the interface support accessibility?

---

## 6. Quantitative Method: Questionnaire

One effective way to collect formative data is through a questionnaire.

A questionnaire allows us to collect structured responses from users. These responses can then be analysed to identify patterns, trends and design issues.

Example rating scale:

```text
1 = Very poor
2 = Poor
3 = Average
4 = Good
5 = Excellent
```

Or:

```text
1 = Strongly disagree
2 = Disagree
3 = Neutral
4 = Agree
5 = Strongly agree
```

## 7. Variables Students Need to Test

For this week, students should understand the main interface variables that can be evaluated.

### 1. Grouping

Grouping is linked to Gestalt principles.

Students should ask:

- Are related items placed together?
- Are sections visually separated?
- Does the layout help users understand relationships between content?
- Are cards, forms, menus or buttons grouped logically?

Example:

```text
A restaurant website should group menu items, prices, dietary labels, and order buttons clearly.
```

Poor grouping example:

```text
Food image at the top, price somewhere else, order button hidden at the bottom.
```

Good grouping example:

```text
Food image, item name, price, description, allergy label, and order button are grouped in one card.
```

---

### 2. Colour Scheme

Colour affects emotion, attention, readability and brand identity.

Students should ask:

- Do the colours match the purpose of the website?
- Is contrast strong enough?
- Are colours used consistently?
- Are important actions visually clear?
- Are colours accessible for users with colour blindness?

Example:

```text
A food website may use warm colours to create appetite and energy, but the text must still be readable.
```

Important note:

```text
Colour should support usability, not replace usability.
```

Do not use only colour to show an error. Add text and icons too.

---

### 3. Regional Structure

Regional structure means how the interface is divided into meaningful areas.

Students should look at:

- header
- navigation
- hero section
- content area
- forms
- cards
- call-to-action areas
- footer

Example structure:

```text
Header → navigation → hero banner → main content → action section → footer
```

Good regional structure helps users know where they are and where to look next.

---

### 4. Logo Design

Logo design should be simple, recognisable and suitable for the brand.

Students should ask:

- Is the logo readable?
- Is it simple enough?
- Does it match the business identity?
- Does it work on mobile screens?
- Does it look good in small size?

Fun point:

> Many strong brand logos are simple enough to recognise even when shown very small.

For an assessment website, students should not only say “the logo looks nice”. They should explain how the logo affects recognition, trust and visual identity.

---

### 5. Time to Complete

Time to complete measures ease of use and efficiency.

Students should ask:

- How long does it take to complete a task?
- How many steps are needed?
- Where do users hesitate?
- Does the interface reduce unnecessary effort?

Example task:

```text
Find a menu item and start an order.
```

Good design:

```text
User can complete the task in 30–60 seconds with minimal confusion.
```

Poor design:

```text
User spends 3 minutes looking for the menu or order button.
```

## 8. Gestalt Principles: Simple Explanation

Gestalt principles explain how people visually organise information.

The main idea is:

> Users do not see isolated objects only. They naturally group, connect and interpret elements based on visual patterns.

In UI design, Gestalt principles help designers create interfaces that feel clear, organised and intuitive.

---

## 9. Key Gestalt Principles for UI Design

### Proximity

Elements close together are seen as related.

UI example:

```text
A product image, product name, price and Buy button should be close together.
```

Assessment use:

Students can use proximity to group related content such as menu categories, contact details, booking options or form fields.

---

### Common Region

Elements placed inside the same boundary are seen as part of one group.

UI example:

```text
A card containing food image, description, price and Add to Basket button.
```

Assessment use:

Students can use cards, banners, tables and boxes to organise content clearly.

---

### Similarity

Elements that look similar are seen as having the same function.

UI example:

```text
All primary buttons use the same colour, shape and size.
```

Assessment use:

Students should keep button styles, headings, icons and navigation consistent.

---

### Closure

Users can recognise incomplete shapes or icons by mentally completing them.

UI example:

```text
Simple icons can still communicate meaning even with minimal detail.
```

Assessment use:

Students can discuss closure when reviewing icons, logos and simplified visuals.

---

### Symmetry

Balanced layouts often feel organised and stable.

UI example:

```text
A portfolio or product display with aligned cards creates a professional appearance.
```

Assessment use:

Students can use symmetry for structure, but may use controlled asymmetry to draw attention to important actions.

---

### Continuation

Users naturally follow lines, paths and sequences.

UI example:

```text
A step-by-step checkout process guides users from basket to payment to confirmation.
```

Assessment use:

Students can use continuation in menus, forms, product lists and user journeys.

---

### Common Fate

Elements that move or change together are seen as related.

UI example:

```text
An accordion menu expands and collapses related content together.
```

Assessment use:

Students can apply common fate in dropdowns, filters, sliders, expandable menus and interactive panels.

---

## 10. Gestalt, Cognition and Perception

Cognition is about how users think, understand, remember and make decisions.

Perception is about how users see and interpret the interface.

Gestalt principles support cognition because they reduce mental effort.

Example:

```text
If related items are grouped clearly, users do not need to mentally work out what belongs together.
```

Poor interface:

```text
Buttons, headings and information are scattered randomly.
```

User reaction:

```text
“Where do I start?”
```

Better interface:

```text
Content is grouped into clear cards and sections.
```

User reaction:

```text
“I understand this page quickly.”
```

---

## 11. Gestalt and User Demographics

Different demographic groups may interpret interfaces differently.

Students should consider:

- age
- digital confidence
- language background
- cultural expectations
- accessibility needs
- device used
- context of use

Example:

```text
A young user may understand icon-only navigation quickly.
An older or less confident user may need text labels with icons.
```

Example for food website:

```text
A traditional restaurant website may need clear menu categories, allergy labels, opening hours and contact details for different user groups.
```

Important teaching point:

> A design that feels obvious to one group may not feel obvious to another.

---

## 12. Gestalt and Accessibility

Gestalt principles can improve accessibility when used carefully.

### Good Accessibility Uses

Proximity:

```text
Labels are placed close to their form fields.
```

Similarity:

```text
All buttons behave consistently.
```

Common Region:

```text
Related content is grouped inside accessible cards or sections.
```

Continuation:

```text
Forms follow a logical top-to-bottom order.
```

### Accessibility Risks

Students must avoid:

- relying only on colour
- using icon-only controls with no labels
- making cards look clickable when they are not
- using weak contrast
- confusing visual order and keyboard order

Important point:

```text
Visual grouping must match screen reader and keyboard navigation order.
```

## 13. Modern Industry Context

Modern UX design is moving towards faster prototyping, AI-supported ideation, accessibility-first workflows and evidence-based decision making.

Students should understand that industry teams now often use:

- Figma for collaborative design and prototyping
- FigJam for brainstorming and workshops
- Stitch or Uizard for AI-generated UI ideas
- Maze or Useberry for prototype testing
- Hotjar or Microsoft Clarity for behaviour analytics
- WAVE, axe DevTools and Lighthouse for accessibility checks
- design systems to maintain consistency across products

The important message is:

```text
Tools can create designs quickly, but HCI knowledge is needed to evaluate whether the design actually works for users.
```

Current design workflows increasingly use AI to generate layouts, design options and prototype ideas. However, human designers still need to check usability, accessibility, ethics, brand fit and user context.

## 14. Figma in This Seminar

Figma is recommended as the wireframe and prototype tool for this module.

Students do not need advanced Figma skills.

They only need to learn how to:

- create a frame
- add text
- add shapes
- group elements
- create simple cards
- use alignment and spacing
- add buttons
- create a basic clickable prototype

Simple Figma workflow:

```text
Create frame → add layout sections → add content → apply Gestalt grouping → add buttons → link screens → test prototype
```

Alternative tools:

- Canva
- Uizard
- Stitch
- Adobe XD
- Pen and paper
- PowerPoint wireframe

Important note:

```text
The tool is not the learning outcome. The HCI decision is the learning outcome.
```

## 15. Recommended 2-Hour Seminar Plan

### 00:00–00:10 — Opening and Warm-Up

Ask students:

```text
When you open a website, how do you know what belongs together?
How do you know where to click first?
What makes a page feel organised or messy?
```

Show them a familiar website and ask:

```text
What do your eyes notice first?
Which items seem grouped?
Which button looks most important?
```

Explain that this is the beginning of Gestalt thinking.

---

### 00:10–00:25 — Mini Explanation: Gestalt in UI Design

Explain the core principles:

- proximity
- common region
- similarity
- closure
- symmetry
- continuation
- common fate

Use simple examples:

```text
Food card = common region
Related form label and field = proximity
Same button colour = similarity
Checkout progress = continuation
Dropdown menu = common fate
```

---

### 00:25–00:40 — Group Activity 1: Gestalt Principles and Assessment

Students work in groups.

Task:

```text
Discuss which Gestalt principles are useful for your assessment website redesign.
Which ones are less relevant?
Explain why.
```

Student worksheet:

```text
Website / page we are reviewing:

Useful Gestalt principles:
1.
2.
3.

Why they are useful:

Less relevant principles:
1.
2.

Why they are less relevant:

One design improvement using Gestalt:
```

Expected outputs:

- proximity for grouping menu items or content
- common region for cards and sections
- similarity for buttons and navigation
- continuation for forms or ordering journey
- accessibility considerations for labels and contrast

---

### 00:40–00:55 — Group Feedback

Each group gives one example.

Prompt:

```text
Tell us one Gestalt principle you would definitely apply in your assessment and why.
```

Tutor response should push them to justify:

```text
How does that improve cognition?
How does that improve usability?
How does that help a specific user group?
```

---

### 00:55–01:10 — Group Activity 2: Cognition, Demographics and Accessibility

Task:

```text
Choose three Gestalt principles and explain how each affects cognition, demographics and accessibility.
```

Student worksheet:

```text
Gestalt principle:
Impact on cognition/perception:
Impact on usability:
Demographic consideration:
Accessibility consideration:
Example improvement:
```

Example answer:

```text
Principle: Proximity
Impact on cognition: Users quickly understand related information.
Demographic consideration: Less confident users need clearer grouping.
Accessibility: Labels should be close to form fields and correctly linked.
Improvement: Place menu item name, price and order button inside one card.
```

---

### 01:10–01:25 — Formative Data Collection Mini Task

Explain:

```text
Now that we have design ideas, we need a way to evaluate them.
```

Students create a short questionnaire to test five variables:

1. grouping
2. colour scheme
3. regional structure
4. logo design
5. time to complete

Example questions:

```text
The page groups related information clearly. 1–5
The colour scheme makes the page easy to use. 1–5
The page structure is easy to understand. 1–5
The logo is simple and recognisable. 1–5
I could complete the task quickly. 1–5
```

Add one open-ended question:

```text
What is one thing you would improve about this interface?
```

---

### 01:25–01:45 — Individual Activity: Figma Exploration

Students open Figma or another tool.

Task:

```text
Create a simple wireframe for one improved page section.
```

Options:

- homepage hero section
- menu card section
- contact form
- booking/order flow
- restaurant information section
- alumni/event card if using previous assessment context

They must apply at least three Gestalt principles.

Minimum design requirement:

```text
1 heading
1 content section
1 grouped card or form
1 call-to-action button
1 accessibility consideration
```

---

### 01:45–01:55 — Peer Review

Students pair up and review each other’s wireframes.

Peer review questions:

```text
Which Gestalt principle is clearly visible?
Is the grouping logical?
Is the visual hierarchy clear?
Is it accessible?
Can the user complete the task quickly?
What is one improvement?
```

---

### 01:55–02:00 — Final Recap

Close with:

```text
Today you used Gestalt principles to explain why an interface feels organised or confusing. You also connected design decisions to cognition, accessibility, demographics, formative data collection and Figma prototyping. This is exactly the type of thinking required for your assessment.
```

Use this as the main classroom task.


## 19. Simple Data Analysis Example

If five users answer a question:

```text
Question: Related information is grouped clearly.
Scores: 4, 5, 3, 4, 4
Average = 20 / 5 = 4.0
```

Interpretation:

```text
Average score is 4.0, so most users agree that grouping is clear. However, one score of 3 suggests that some users may still find the grouping only average. The design could be improved by making section boundaries clearer.
```

This helps students move from raw data to design insight.

## 22. Fun Tech Facts

### Fun Fact 1: Users Scan Before Reading

Most users visually scan a page before reading details. This is why layout, spacing and hierarchy matter.

### Fun Fact 2: Grouping Reduces Brain Work

When related items are visually grouped, users spend less effort understanding the page.

### Fun Fact 3: Consistent Buttons Build Trust

If every button looks different, users become unsure which actions are important.

### Fun Fact 4: AI Can Generate UI, But It Cannot Guarantee Usability

AI tools can quickly create layouts, but designers still need to check user needs, accessibility, ethics and task success.

### Fun Fact 5: Accessibility Supports Everyone

High contrast helps visually impaired users, but also helps anyone using a phone in bright sunlight.

## 24. Tutor Script for Assessment Link

Use this when students ask why Gestalt matters:

> In your assessment, you are not expected to simply say that a website looks good or bad. You need to explain why the design works or does not work. Gestalt principles give you academic language to explain layout, grouping, consistency, visual structure and user perception.

## 25. Final Teaching Message

End with:

> A good interface helps users understand relationships without making them think too hard. Gestalt principles help us organise the visual structure, questionnaires help us collect evidence, and Figma helps us turn improvement ideas into a prototype.
